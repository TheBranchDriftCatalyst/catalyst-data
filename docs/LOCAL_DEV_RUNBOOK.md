# Local Dev Runbook — catalyst-data + catalyst-llm

Two-stack local-dev recipe. Each stack runs its own `tilt up` against its own
Tiltfile; they do not share a Tilt process. Run them in two terminals.

| Stack          | Tilt port | Backend                                            |
| -------------- | --------- | -------------------------------------------------- |
| catalyst-data  | 10350     | docker-compose (MinIO, Neo4j+n10s) + local procs   |
| catalyst-llm   | 10351     | shared k3d cluster `catalyst-dev` + native Ollama  |

The two stacks intentionally use different infra rails — do not unify them.
catalyst-data's dev surface is "S3 + Neo4j + Dagster + Vite", catalyst-llm's is
"k3d + Ollama + LangGraph". Prod (`tilt-ops/Tiltfile` in each repo) is a
parallel rail; do not edit it from the dev path.

---

## One-time prereqs

Tools (install via Homebrew unless noted):

```bash
brew install tilt docker k3d go-task mise direnv
# uv comes from mise (see ~/.config/mise/config.toml) but `brew install uv` works too.
```

- Docker Desktop must be running (Compose v2 + Buildx).
- `direnv` must be hooked into your shell (`eval "$(direnv hook zsh)"`) so the
  `.envrc` files in each repo auto-load.
- `mise` provides the per-repo Python (3.12) and tooling pins.

Repo-local one-time bootstrap:

```bash
cd ~/catalyst-devspace/workspace/catalyst-data
direnv allow              # loads .envrc (chains into .envrc.cluster for secrets)
mise install              # installs Python 3.12 + project tooling
uv sync                   # populates the workspace .venv (Dagster, FastAPI, boto3, etc.)
cd packages/catalyst-data-ui && npm install && cd -

cd ~/catalyst-devspace/workspace/catalyst-llm
mise install
yarn install              # SDK + playground deps
```

Env vars / secrets used by the dev stacks (all are sourced from
`.envrc.cluster`, which is auto-generated by
`scripts/ops/pull-dev-secrets.sh` against the live k8s cluster):

| Var                  | Used by                                          |
| -------------------- | ------------------------------------------------ |
| `CONGRESS_API_KEY`   | `task seed:congress`, congress integration tests |
| `OPENAI_API_KEY`     | LLM-touching code paths (LiteLLM proxy)          |
| `LLM_API_KEY`        | LiteLLM proxy (same value as OPENAI_API_KEY)     |
| `HF_TOKEN`           | Whisper / pyannote diarization                   |
| `DAGSTER_S3_*`       | MinIO endpoint (overridden in `.envrc`)          |

The catalyst-llm playground also needs `k8s/local/litellm-secrets.env` with a
`master-key=sk-...` line — present already (copied from
`litellm-secrets.env.example`). The Tiltfile reads this and injects
`VITE_LITELLM_KEY` into the playground.

```bash
cd ~/catalyst-devspace/workspace/catalyst-data
tilt up                   # default Tiltfile; --port=10350 if 10350 is busy
```

What comes up:

| Resource           | Surface                                            |
| ------------------ | -------------------------------------------------- |
| `minio`            | S3 API http://localhost:9000 (minio / minio123)    |
| `minio-init`       | one-shot: creates `dagster` bucket                 |
| `neo4j`            | http://localhost:7474 (neo4j / neo4j-homelab)      |
| `neo4j-n10s-init`  | one-shot: n10s constraint + `graphconfig.init`     |
| `dagster-dev`      | webserver http://localhost:3000 (all 3 locations)  |

| `viewer-ui`        | Vite http://localhost:5173/viewer/                 |
| `bench:run` etc.   | manual triggers (Tilt button)                      |

MinIO Console: http://localhost:9001
Neo4j Browser: http://localhost:7474 (use the connect URL `bolt://localhost:7687`).


### Verifying the Neo4j + n10s bridge (new this session)

The `neo4j-n10s-init` resource runs once and configures the n10s graphconfig.
There's no `cypher-shell` on the host — query through the container:

```bash
docker exec catalyst-data-neo4j-dev \
  cypher-shell -a bolt://localhost:7687 -u neo4j -p neo4j-homelab \
  'CALL n10s.graphconfig.show()'
```

Expected output starts with `param, value` and includes `"handleVocabUris", "IGNORE"`.
If it returns "GraphConfig is not initialized", re-trigger the init resource:

```bash
docker rm -f catalyst-data-neo4j-n10s-init
tilt --port=10350 trigger neo4j-n10s-init
```

## Known issues + workarounds

### `neo4j-n10s-init` flakes on first boot (fixed this session)

`dc_resource` in Tilt only tracks "container started" — it does NOT honor
docker-compose's `depends_on.condition: service_healthy`. So the init
container used to fire immediately and fail with
`Unable to connect to neo4j:7687`.

Fix lives in `docker-compose.dev.yml`: the n10s-init entrypoint now retries
for up to 120s (`for i in $(seq 1 60); do cypher-shell ... && break; sleep 2; done`)
before issuing the constraint + `n10s.graphconfig.init()`. Also switched the
entrypoint from a YAML folded scalar (`>`) to a literal block (`|`) — the
folded form was silently joining the multi-line cypher into a single line,
which broke the `CREATE CONSTRAINT` invocation.

If you see "Bolt reachable after $i attempts." (literal `$i`), it's the
docker-compose interpolation eating `${i}` — the entrypoint uses `$$i` to
escape it for Compose.

### Dagster scheduled jobs fail at boot

`bills_discovery_schedule`, `members_discovery_schedule`, etc. run on a
schedule and may fail-fast on first boot (missing partitions, no LLM_API_KEY
loaded in the dagster-dev process, etc.). These failures are visible in the
`dagster-dev` resource logs but are **not** a Tilt bring-up issue — the
webserver is up and reachable. Investigate via the Dagster UI at
http://localhost:3000.

### Port 7474 / 7687 collisions

If something else (a previous Neo4j Desktop, a different project's Neo4j
container) is already on 7474 or 7687, the `neo4j` resource will fail to
bind. Find and stop the conflicting service:

```bash
lsof -nP -iTCP:7474 -iTCP:7687 | grep LISTEN
docker ps --filter publish=7474,7687
```

### `catalyst-langgraph` `update=in_progress` doesn't mean broken

The Tilt UI may show `update=in_progress` while a docker image rebuild runs
in the background after a code change. The existing pod stays up and `/healthz`
keeps returning 200. The new image rolls out when the build completes.

### LLM-touching paths need `LLM_API_KEY`

The Tilt process inherits whatever was in the parent shell. `tilt up` itself
doesn't load direnv, so make sure your `.envrc` is allowed and you've cd'd
into the repo before running it, otherwise Dagster assets that hit LiteLLM
will fail with 401s.

### k3d cluster missing

`k3d cluster list` should show `catalyst-dev`. If it doesn't:

```bash
/Users/panda/catalyst-devspace/infra/k3d/k3d-up.sh   # creates if absent
# Force recreate if it's wedged:
/Users/panda/catalyst-devspace/infra/k3d/k3d-up.sh --force
```

### `mc` / `cypher-shell` not on host

Both ship inside their respective containers — drive them via `docker exec`:

```bash
docker exec catalyst-data-minio-dev mc ls local/dagster
docker exec catalyst-data-neo4j-dev cypher-shell -u neo4j -p neo4j-homelab 'MATCH (n) RETURN count(n)'
```

## Tear-down

```bash
# Each terminal: Ctrl-C in the `tilt up` foreground, then:
tilt down                 # for the repo you're cd'd into

# Optional, nukes persistent state:
rm -rf .test-output/minio-data .test-output/neo4j-data
```

The shared k3d cluster persists across catalyst-llm `tilt down` calls
intentionally — bring it down explicitly with
`/Users/panda/catalyst-devspace/infra/k3d/k3d-down.sh` if you really want it
gone.
